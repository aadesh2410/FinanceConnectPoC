The Problem

Banks run on Excel. Auditors don't.

Every financial institution has hundreds of critical spreadsheets — risk models, credit registers, trade exposure logs — living outside the enterprise data platform. Ungoverned. Undocumented. Untraceable.

📊

Ungoverned data

Business-critical calculations sit in Excel files on shared drives. No lineage, no audit trail, no single source of truth.

⏱️

Manual migration is slow

Onboarding one EUC into Snowflake takes days — analysts reverse-engineer schemas, guess data types, and hand-write DDL.

🔍

Regulators want visibility

BCBS 239, SR 11-7, model risk management — all demand governed, versioned, reviewable data pipelines. Excel doesn't cut it.

The Solution

An AI-assisted pipeline from workbook to warehouse.

Drag an Excel file in. Claude (or a deterministic local heuristic) reads every sheet, infers table structure, column names, data types, and semantics. A reviewer approves — or edits — the schema. One click executes the DDL and upserts the data into Snowflake.

The Signature Metric

Schema Readiness Score — one number to trust.

Every inferred schema gets a composite readiness score before a human sees it. Reviewers know instantly whether to skim or scrutinise.

The Formula
schemaReadinessScore = (avgTableConfidence × 0.5) + (avgSheetConfidence × 0.3) + ((1 − lowConfidenceRatio) × 0.2)
50%

avgTableConfidence

Average AI confidence across all inferred tables — the model's own certainty about the schema it proposed.

30%

avgSheetConfidence

Average region-detection confidence across sheets — did the parser cleanly identify header and data boundaries?

20%

1 − lowConfidenceRatio

Fraction of columns above 80% confidence — penalises schemas with too many ambiguous or low-signal fields.

Per-column confidence factors
Header clarity
Is the column label unambiguous and descriptive?
Value consistency
Do the sampled values follow a single pattern?
Type match rate
What % of values conform to the inferred type?
Population ratio
How often is the column populated vs. blank?
Determinism & Consistency

Same file in, same answer out — always.

AI is powerful but non-deterministic. Finance Connect wraps Claude in a hash-guarded workflow so that identical uploads produce identical, human-approved results every time.

  • Every uploaded file is MD5-hashed server-side the moment it arrives — before any analysis.
  • On re-upload, the hash lookup finds the previous job — no new AI inference call is made for the same binary file.
  • The previous approved schema (human-reviewed and signed off) is loaded as the stable reference.
  • Schema diff runs against that approved version so human edits are always preserved across re-uploads.
  • In Local (heuristic) mode, inference is fully deterministic by design — same file = byte-for-byte identical output.
  • In Claude AI mode, the hash guard means Claude is called once per unique file version, ever.
